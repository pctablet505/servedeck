# Servedeck v2 — one stack for local models

**Status:** design, 2026-09-12. Written before touching code, at the owner's request:
"refactor and rewire local_llm, the vllm stuff, our fixes, servedeck, and the codex / kimi /
vscode wiring so that we don't struggle all the time fixing random flaws."

**Owner rules this design keeps (do not re-litigate):** full native context per model;
reasoning always on, and chat-completions clients always receive `reasoning_content`;
latest vLLM; never `--enforce-eager` as a fix; servedeck is the control path; the GLM and
Flash-Next patches must not be lost; port 8000 is not ours; no sudo, no host network changes.

---

## 1. Why it keeps breaking

Every failure of the last week is one of five root causes. The design removes the causes, not
the symptoms.

| # | Root cause | Symptoms it produced |
|---|---|---|
| R1 | **A model's identity lives in many files.** Its public name, port and context length are copied into `chatLanguageModels.json`, `~/.codex/config.toml`, three proxy units, `servedeck.toml`, `local_llm/.config`, experiment scripts. | 404 "model does not exist" twice (27B rename 09-11, Flash-Next 09-12); the Flash-Next proxy silently pointed at the 27B's port; `run_experiment_flashnext.py` still uses a dead name. |
| R2 | **Two control planes share one mutable bash file.** `llm` and servedeck both write `local_llm/.config`, which is sourced last-assignment-wins; servedeck launches by shelling out to the launcher that re-reads that file. | `.config` poisoned three times; Flash-Next's `EXTRA_ARGS` handed to the 27B; the 27B killed at boot by `--prefix-match-unit`; `state/extra_args.json` stash-and-restore choreography. |
| R3 | **Normalisation lives in per-model side proxies, not in the gateway.** `:8003`, `:8005`, `:8006` each front one fixed upstream port; the real gateway on `:8010/v1` forwards raw bytes. | Clients must know which port is "safe" for which model; a port swap breaks a proxy; the gateway is unusable for VS Code; three units run one file with an env var. |
| R4 | **Process lifecycle is improvised.** vLLM runs inside the dashboard's cgroup (`KillMode=control-group`); dashboards get started from terminals; the unit crash-loops at boot; adoption walks `/proc`. | Stopping the dashboard killed the model; two dashboards on one state dir; `servedeck.service` dead with a hand-started copy answering :8010; a resident small model can block a big-model boot by 500 MiB. |
| R5 | **Too much surface.** ~28,000 lines (14.8k code, 13.9k tests) for a local dashboard: a hand-rolled Prometheus parser, a 462-line boot-phase regex machine "transcribed verbatim", per-architecture KV estimators with calibration constants, a 1,750-line supervisor, a 1,950-line `app.js`. Nearly all tests run against mocks. | Two audit passes and a live sweep found F1–F14 plus dozens more; every fix round adds surface that carries the next defect; the live boot/switch/adopt paths, the ones that actually fail, have no end-to-end test. |

A sixth, smaller cause: three vLLM builds (`vllm-glm53`, `vllm-qwen38next`, `.venv-llm-029`)
with their patches living only as commits in checkouts, and one launcher script per model.

## 2. The design

One repository (`servedeck`, it is already public and already the control path), one Python
package, one long-running unit, one transient unit per model, one endpoint for every client.

```
clients (VS Code, Codex, Kimi, Claude Code, scripts, tests)
        │  http://127.0.0.1:8010/v1   — the only URL anyone configures
        ▼
┌───────────────────────── servedeck.service ─────────────────────────┐
│  gateway   /v1/models = every live model + its aliases              │
│            /v1/chat/completions, /v1/responses, /v1/embeddings      │
│            routes by `model` → port; mirrors reasoning→reasoning_content│
│  control   /api/*  + `servedeck` CLI: status · start · stop · switch │
│            · wire · doctor                                          │
│  dashboard one page: what is live, KV/context headroom, boot log    │
└──────────────┬──────────────────────────────┬───────────────────────┘
               │ systemd-run --user           │ systemd-run --user
               ▼                              ▼
   model-<id>.service (main slot,     model-<id>.service (resident slot,
   one at a time: GLM / Flash-Next    always on: LFM2.5-350M, …)
   / 27B)                              
               ▲                              ▲
               └──── models.toml: the single source of truth ─────────┘
```

### 2.1 `models.toml` — the registry (fixes R1)

One file, checked into the repo, validated on load. Everything else is derived from it.

```toml
[gpu]
total_mib   = 97887
margin_mib  = 1024          # never handed to any model

[models.flashnext]
id        = "Qwen3.8-Flash-Next-Uncensored-NVFP4"
aliases   = ["qwen38-flash-next", "flashnext"]          # every name a client ever used
repo      = "mazinb/Qwen3.8-Flash-Next-Uncensored-NVFP4"
slot      = "main"                                       # exclusive GPU slot
port      = 8001
build     = "qwen38next"                                 # → builds/qwen38next
ctx       = "native"                                     # full native context, always
reasoning = { parser = "qwen3", mirror_content = true }
tools     = { parser = "qwen3_coder" }
flags     = ["--mamba-ssm-cache-dtype", "bfloat16", "--speculative-config", '{"method":"mtp","num_speculative_tokens":3}']
env       = { VLLM_USE_FLASHINFER_SAMPLER = "0" }

[models.lfm2]
id        = "LFM2.5-350M"
repo      = "LiquidAI/LFM2.5-350M"
slot      = "resident"                                   # co-resident, always on
vram_mib  = 3300                                         # its budget; util is derived
port      = 8007
build     = "stock"
ctx       = 32768
tools     = { parser = "lfm2" }
```

Rules the loader enforces: ids and aliases unique across the file; ports unique and never 8000
or 8010; `sum(resident vram) + margin < total`; a `main` model's utilisation is **computed at
launch** as `(free_mib − margin) / total`, so residents can never make a big model refuse to
boot and nobody ever tunes `0.91 / 0.95 / 0.96` by hand again (the owner's "0.95 on purpose"
becomes "everything that is free", which is what was meant).

vLLM is launched with `--served-model-name <id> <alias> <alias>…`, so **every old name keeps
working**. The 404 class of bug is gone by construction.

### 2.2 Supervisor on transient units (fixes R2, R4)

`servedeck start flashnext` runs, in effect:

```
systemd-run --user --unit=model-flashnext --collect \
  -p Restart=on-failure -p RestartSec=10 \
  -E VLLM_USE_FLASHINFER_SAMPLER=0 … \
  /home/…/builds/qwen38next/.venv/bin/vllm serve mazinb/… --served-model-name … --port 8001 …
```

What this buys, for free, from systemd:

- The model is **not** in the dashboard's cgroup. Restarting servedeck never touches a model.
  `KillMode` stops being a topic.
- Logs go to journald (`journalctl --user -u model-flashnext`); boot progress is a tail of the
  journal for four known markers (weights loaded, KV size, graphs captured, startup complete),
  not a state machine.
- Adoption is `systemctl --user list-units 'model-*'` plus a port probe. No `/proc` walking,
  no pattern matching, no self-match trap.
- Crash-vs-stopped is `systemctl --user show -p Result,NRestarts`. Restart policy and
  crash-loop ceilings are unit properties (`StartLimitBurst`), not Python.
- The `main` slot is exclusive: `switch` = stop the current main unit, wait until
  `nvidia-smi` reports the memory back, start the next. Residents are untouched.

There is no `.config`, no `qwen-server-run.sh`, no `EXTRA_ARGS` stash. The `llm` CLI is
retired; `servedeck` is the CLI. The GPU power-cap boot service stays as it is (it is not a
model concern).

Desired state is one small JSON (`state/desired.json`: `{main: "flashnext" | null,
residents: ["lfm2"]}`), written only by an explicit command, read at servedeck startup to
reconcile. That rule from the current design is right and stays.

### 2.3 One gateway, normalising (fixes R3)

`:8010/v1` becomes the endpoint every client is configured with, and the three side proxies
are retired.

- `GET /v1/models`: the union of every live model, each listed under its id **and** each
  alias, with `max_model_len` so clients can size context without a second config.
- `POST /v1/chat/completions`: resolve `model` (id or alias) → port. If the target model's
  registry entry says `mirror_content`, copy `reasoning` into `reasoning_content` in both the
  JSON body and every SSE delta (the logic that lives in `flashnext-reasoning-proxy/proxy.py`
  today, moved in with its tests). Optional per-model `min_output_tokens` floor (the GLM
  thinking-budget fix) becomes a registry field.
- Effort presets (`glm53-flash-high`, `-low`) become aliases carrying a request overlay
  (`reasoning_effort` / `max_tokens`) in the registry, replacing `glm53-effort-proxy`.
- `/v1/responses` and `/v1/embeddings`: routed, otherwise untouched (Codex is already
  correct on the responses API).
- While the main slot is switching: `503` with `Retry-After` and a JSON error naming the
  model that is booting, instead of a connection refused.

### 2.4 `servedeck wire` — generated client configs (fixes R1 for clients)

One command reads the registry and rewrites, idempotently, with a dated backup and a diff:

- `~/.config/Code/User/chatLanguageModels.json` — one entry per model + effort alias,
  `url = http://localhost:8010/v1/chat/completions`, tokens from the registry.
- `~/.codex/config.toml` — one provider (`base_url = http://127.0.0.1:8010/v1`,
  `wire_api = "responses"`), one profile per model.
- Kimi and Claude Code local-endpoint config, where present.

`servedeck doctor` then proves it: for every generated entry, `GET /v1/models` at the
configured URL must list that exact id. Every client config drift becomes a red line in
`doctor` instead of a 404 in the editor an hour later.

### 2.5 Dashboard and CLI (UX)

The page today shows dashes because its plumbing cannot see the model. v2 shows one page,
driven entirely by `/api/state`, which is itself derived from the registry plus live probes:

- **Live models**: for each unit: id (+aliases), slot, port behind the gateway, context, KV
  used/free, requests in flight, tokens/s, uptime, restarts.
- **Headroom**: free VRAM, how many full-context requests still fit, how many small ones
  (the current `capacity`/`parallelism` arithmetic, kept as a library; measured beats
  estimated).
- **Controls**: start/stop a resident, switch the main slot, wire clients, run doctor. Each
  control is one POST and one SSE stream of the unit's journal until READY or failure.
- **Boot log** tail. **History**: last 20 unit results from `journalctl`, not a JSONL.

The same information is available as `servedeck status` in the terminal, because the owner's
agents (Codex, Claude Code) live in terminals.

### 2.6 Builds and patches (the sixth cause)

`builds/<name>/` holds a `build.sh` that produces `.venv` from a pinned upstream vLLM commit
plus `patches/*.patch` (exported with `git format-patch` from the fork checkouts once, then
maintained as files). `builds/stock/` is the plain wheel used by the 27B and LFM2. "Don't lose
the patches" becomes a property of the repo, and upgrading a build is `git rebase`-free:
bump the base commit, re-apply the patch files, run the model's smoke test.

### 2.7 Tests that exercise what actually fails

- **Unit** (fast, no GPU): registry validation, alias routing, reasoning mirroring on recorded
  vLLM responses (streaming and not), config generation round-trip, the capacity library.
- **End to end** (real vLLM, ~90 s): the owner's point — LFM2.5-350M boots in a minute and
  costs 3 GiB, so the suite boots it on a scratch port as a *resident* and exercises start,
  adopt-after-servedeck-restart, stop, gateway `/v1/models` aliases, a streaming tool call,
  `doctor`. A second tiny fixture with a thinking mode (Qwen3-0.6B, `--reasoning-parser
  qwen3`) covers the `reasoning_content` mirror on a real stream. These replace the mocked
  supervisor tests as the thing that must pass before anything merges.
- **Mutation check** on the gateway and registry modules, per the standing rule that a fix
  ships with proof the test catches its absence.

Target size: under 5,000 lines including tests. Modules kept from today: `capacity`,
`kvcalc`, `parallelism`, `metrics` (rewritten on `prometheus_client.parser`), the mirroring
logic from `proxy.py`, and the pure JS render helpers with their `dukpy` tests. Modules that
disappear: `supervisor` (systemd does it), `procctl`, `phases`, `updetect`, `shellconfig`,
`legacy`, `history`, `logtail`, `preflight` (folded into `doctor`), the three proxies, `llm`
and every launcher script.

| 3 | `wire` flips every client to :8010. Stop and disable `flashnext-reasoning-proxy`, `qwen27b-reasoning-proxy`, `glm53-effort-proxy`. | `doctor` green; a two-turn VS Code exchange re-sends reasoning. | re-enable the three units |
| 4 | Supervisor v2 on `systemd-run`; `lfm2-350m.service` becomes `model-lfm2` under it; the main model is adopted, not restarted. | e2e suite against LFM2 on a scratch port; then one real switch 27B → Flash-Next → 27B observed. | old units still on disk, disabled |

model, and it is done once, announced.

## 5. Decisions taken in this document

1. `servedeck` is the single repo; `local_llm`, the proxies and `lfm2-350m` fold into it.
2. The `llm` CLI and `.config` are retired, not maintained in parallel.
3. Every client, including Codex and Kimi, uses `:8010/v1`; no client is ever pointed at a
   model's own port again.
4. Main-slot utilisation is computed from free memory, not configured.
5. Old model names are kept as aliases forever; nothing is renamed for clients.
