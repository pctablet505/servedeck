## 2. The plan, in order

Each step names who does it, what it removes, and how it is verified. Steps 0-2 are the
whole "no friction" outcome; 3-4 are the debt.

### Step 0 — owner, 5 minutes, sudo (unblocks unattended boots and kimi)

```
sudo tee /etc/sysctl.d/90-servedeck.conf <<'EOF'
kernel.yama.ptrace_scope = 0
fs.inotify.max_user_watches = 1048576
fs.inotify.max_user_instances = 1024
EOF
sudo sysctl --system
sudo nvidia-smi -pl 485
```
Verify: `cat /proc/sys/kernel/yama/ptrace_scope` → 0 after a reboot; `kimi` starts with VS Code
open. Fixes F10, F15, F16. After this, `needs_tty` comes out of `models.toml`.

### Step 1 — cutover to v2 (fixes F1-F9)

Runbook: `docs/CUTOVER-2026-09-12.md` steps 3-9, with two amendments learned today:

1. **Add adoption of an unmanaged listener** to v2 before step 3: if a registered model's
   port answers `/v1/models` with the registered id and no `model-*` unit owns it, `control`
   records it as the main-slot holder (`adopted_pid`) and the gateway routes to it. Then
   step 3 is zero-downtime: v2 takes `:8010` while Flash-Next keeps serving from v1's
   launch. Ships with a gate test (start LFM2 by hand outside v2, then adopt). Without this,
   step 3 costs one Flash-Next restart, which is acceptable but should be a choice.
2. **Move model ports off the collision range**: `:8101`-`:8107` for models, gateway stays
   `:8010`. Registry-only change; nothing else on the box uses 81xx. Doctor already reports a
   foreign holder.

Then, in this order, each with the runbook's verify/undo:
- step 3: v2 takes `:8010` (`systemctl --user stop servedeck.service`, install v2 unit, start).
- step 5: `servedeck wire --apply` — VS Code, Codex, Kimi all get exactly one URL,
  `http://127.0.0.1:8010/v1`, every registry model listed under its id and aliases, thinking
  on. Kimi keeps its cloud entries. Check the wire bug noted below first.
- step 6: stop and disable `flashnext-reasoning-proxy` and `qwen27b-reasoning-proxy`; the
  gateway mirrors `reasoning_content` (gate test proves it on Qwen3-0.6B).
- step 7: first big-model launch under v2: switch to the 27B via the page, then back to
  Flash-Next. Registry flags now carry the KV offload and 16 seqs.
- step 8: archive `local_llm` (`.config`, `llm`, `bin/`) to `local_llm-archive-2026-09/`;
  the only live readers were v1 and the golden test, which moves to a registry-vs-launcher
  check.
- step 9: merge `v2` → `main`, push (owner-gated).

Result: one URL, one page, one file (`models.toml`), `servedeck switch <model>` from any
terminal, and `servedeck doctor` as the single answer to "why is it not working".

**Wire bug to fix before step 5:** the dry-run drops LFM2 from VS Code instead of routing it
via `:8010`. Every registry model belongs in every client; a stopped model answers 503 with
a reason, which is the point of the gateway.

### Step 2 — remove what the cutover makes dead (fixes F11, F13, F14)

- delete `lfm2-350m.service` (v2 unit `model-lfm2` replaces it; keep the file in backups).
- commit each fork's working tree to a local branch (`local/servedeck-2026-09`) so a
  checkout cannot lose the patches; `builds/patches/` stays the export and `check.sh` the
  drift alarm. Today's offload patch belongs there too.
- delete `local_llm/.venv-llm` (3.5 G). Keep `.venv-llm-029`: it is `[builds.stock]`.
- `models.toml`: resolve the 2048-vs-8192 batched-tokens question by reading the live
  process argv, then pin the truth; add a gate test that compares every model's registry
  argv with what its unit actually ran.

### Step 3 — the UX layer (what "smooth" means day to day)

- **One command:** `servedeck switch flashnext` / `servedeck status` / `servedeck doctor`
  from any terminal (CLI exists on v2; add a `~/.local/bin/servedeck` shim at cutover).
- **Wire on every start:** `control.start` runs `wire --apply` when the model set changes, so
  VS Code, Codex and Kimi never go stale again; the page shows "clients wired ✓".
- **Boot ETA on the page:** v2's main panel shows phase + elapsed; restore v1's ETA line from
  `state/history.jsonl` so a 3-minute boot does not look hung.
- **Presets as models:** GLM's effort presets already appear as separate ids
  (`glm53-flash-low/high`); do the same for Flash-Next thinking on/off so a client never
  needs `chat_template_kwargs`.
- **README of five lines** at `servedeck/README.md`: start the page, switch a model, wire
  clients, run doctor, where the logs are. Everything else links from it.

### Step 4 — docs and hygiene (fixes F17)

- One docs home: `servedeck/docs/`. Move the GLM notes and the vllm-qwen38next SETUP/notes
  under `docs/models/<name>/`; `local_llm/docs` goes with the archive. Delete `.bak` files.
- Every memory-note claim that names a path gets re-verified against the merged tree.
