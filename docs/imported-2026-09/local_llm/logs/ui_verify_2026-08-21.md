# UI verification — AlgoTrading PyQt desktop, 2026-08-21 (living doc)

Standing task from the owner: **manual, functional verification of the desktop UI —
"rendering and visibility is not enough; it must be properly functional with the UX a
real user would expect."** A control that fires but leaves the user with no usable
outcome is a defect, not a pass. This file is the running record so other agents can
pick up or collaborate without re-deriving anything.

## Acceptance standard

- Per user journey: input → action → wait → **observable outcome a real user would
  accept** (real numbers, real rows, real chart data, clear error feedback).
- Every defect logged with: page, repro steps, observed vs expected, severity
  (CRASH / BLOCKED / DEGRADED / CONFUSING / NITPICK).
- No live-money path is started (no live session, no order placement, no
  `LIVE_TRADING_ENABLED`, no kill-switch toggle). No training runs (GPU is held by
  the local vLLM server; charter §1.11). Paper-trading read-only.
- **Owner ruling 2026-08-21: no active Kite subscription.** Everything requiring a
  Kite login/broker session (auth login flow, live-sim session start, broker-routed
  order placement, full historical downloads) is OUT OF SCOPE — verify UI only up to
  the "broker required" boundary. The observed "Session file exists but token is
  invalid/expired" state on the auth page is the CORRECT expected state, not a defect.
  Broker-free journeys (charts, backtest, screener, WF, regime, portfolio, risk,
  compare, model vault, reports, training monitor, indices, database, CLI terminal,
  settings load) are in scope.
- No screenshots unless a defect cannot be established from the widget tree.

## Observations / notes (non-defect)

- `ohlcv_*` SQLite tables empty by design (parquet is the store) — recorded so a
  future agent doesn't "fix" pages that read parquet correctly.
- **Boot-environment trap (cost one full re-run, 22:35–22:50):**
  `load_workspace_env()` reads `.env` from `Path(__file__).parents[4]` — the root of
  the *checkout the code was imported from*. The first driver run silently imported
  `algotrading` from the canonical tree (venv editable install; script-dir
  `sys.path` shadowing) where a `.env` exists, so the data layer booted — against the
  **dead-lineage code** (the very shadow the import check exists to catch; run 1's
  window was not main's code). After forcing the worktree onto `sys.path` there was
  no `.env` in the worktree root, so the app booted *degraded* ("Failed to initialize
  data layer: ALGOTRADING_WORKDIR not found in environment or .env file"). Correct
  boot = worktree import **and** `ALGOTRADING_WORKDIR` exported (driver now sets it
  and records `DATA_LAYER`). For a real user on a fresh clone the documented flow is
  `.env.example` → `.env` — **now fixed** (finding #4, `b86eddd6`/`e471892b`): the
  degraded-boot banner names the file to create and the guide documents the step.
- App boot offscreen with real workdir + env var: service manager + simulation
  manager initialize cleanly.
