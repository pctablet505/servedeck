# Cutover runbook — v1 → v2

Every step states what changes, how it is verified, and how to undo it. Steps 1-2 are rehearsals and
change nothing the owner uses. Step 3 onwards are live; each is announced before it runs.

**Standing constraints.** No sudo in an agent session. Port 8000 is `ats-optimizer` and is never
touched. Nothing binds anything but 127.0.0.1. Reasoning stays on, and every chat-completions client
must receive `reasoning_content`. Full native context per model, except GLM, pinned to its validated
327,680 (§2.1). No `--enforce-eager`, ever.

**Preconditions (all must hold before step 3)**
- P4 merged into `v2`; the whole suite green; `servedeck doctor` exits 0 or explains every failure.
- P7's acceptance gate green (§8): real LFM2 boots, switches, coexists; the reasoning mirror proven
  on a real Qwen3-0.6B stream; a failed boot does not loop.
- P6's telemetry recording, so anything that goes wrong during the cutover leaves evidence.
- Backups taken this session: `~/Projects/local_llm/backups/2026-09-12/` (client configs, units) and
  `builds/patches/` (the fork patches, drift-checked by `builds/*/check.sh`).

## Step 1 — Rehearse v2 on a spare port (no risk)

Run v2 on `:8011` with its own state dir while v1 keeps serving `:8010`.

```
SERVEDECK_STATE_DIR=~/Projects/servedeck/state-rehearsal servedeck --port 8011 &
servedeck --url http://127.0.0.1:8011 doctor
servedeck --url http://127.0.0.1:8011 models
```
**Verify:** the dashboard renders; `/api/state` shows the real GPU and the live `:8007` resident as
*unmanaged* (it belongs to v1's unit, not to a `model-*` transient unit); `doctor` reports the three
stopped big models as stopped, not as failures.
**Undo:** kill the rehearsal process and delete `state-rehearsal/`; nothing else touched.
(Not `/tmp`: this box mounts /tmp as RAM, so a rehearsal's state would vanish on
reboot exactly when you want to compare it against what v1 had.)

## Step 2 — Rehearse a managed model (no risk to the owner's models)

Through the rehearsal instance, start a second LFM2 as a transient unit on a scratch port
(`sd-test-*`, port 8050+), exercise it through the gateway, stop it, confirm the VRAM came back.
This is P7's gate run against the assembled product rather than the libraries.
**Undo:** `systemctl --user stop sd-test-*`.

## Step 3 — v2 takes `:8010` (first live step)

The 27B is currently down, so `servedeck.service` has no model in its cgroup and stopping it is safe
(it also now carries `KillMode=process`).

```
systemctl --user stop servedeck.service
cp v2's systemd/servedeck.service ~/.config/systemd/user/servedeck.service   # KillMode=process, TimeoutStopSec=15, StartLimitBurst=3
systemctl --user daemon-reload && systemctl --user start servedeck.service
curl -s :8010/api/health && curl -s :8010/v1/models
```
**Verify:** `/api/health` ok; `/v1/models` lists the live resident under its id *and* aliases;
the page loads; `journalctl --user -u servedeck.service` shows one clean start, no restart loop.
**Undo:** restore the v1 unit file from `backups/2026-09-12/`, `daemon-reload`, start. v1's state dir
is untouched by v2 (different schema version, and v2 migrates on read without writing v1 back).

## Step 4 — LFM2 stays stopped

LFM2 stays stopped; `lfm2-350m.service` has been disabled (2026-09-16); do not add it to
residents. Reason: owner directive 2026-09-16 — by default servedeck runs one model, and the
LFM2 resident is opt-in mechanical/no-intelligence tooling, not an always-on service.
**Undo:** `systemctl --user enable --now lfm2-350m.service` brings back the old unit; the
registry entry (`servedeck start lfm2`) remains available whenever it is actually needed.

## Step 5 — Wire every client to `:8010`

```
servedeck wire                  # dry-run: a unified diff per target
servedeck wire --apply          # dated backups under state/backups/<date>/
servedeck doctor
```
**Verify:** `doctor` resolves every id in every client config against `:8010/v1/models`; VS Code
answers from a real request (reload the window first); `codex` starts and answers; Kimi's
`default_model` points at `:8010` with thinking enabled.
**Undo:** `servedeck wire --restore <date>`, or copy back from `state/backups/<date>/`.

## Step 6 — Retire the side proxies

```
systemctl --user disable --now flashnext-reasoning-proxy.service qwen27b-reasoning-proxy.service
```
**Verify before disabling:** a two-turn exchange through `:8010` that re-sends `reasoning_content`
(proven generically by P7's Qwen3-0.6B test; repeat it here against whichever big model is live).
**Undo:** re-enable both units; they are unchanged on disk.

## Step 7 — The first big-model launch under v2 (the unprovable-by-tiny-models step)

```
servedeck start qwen27b         # or glm53; Flash-Next still needs a tty, see below
```
**Verify:** the boot progress streams to the terminal and the page; util was computed from free VRAM,
not configured; `--max-model-len` is the model's native 262,144; the KV size matches the prediction
within the margin P7 measured; VS Code gets an answer *with* `reasoning_content`; `switch` to another
main model releases the VRAM before the next one starts.
**Undo:** `servedeck stop qwen27b`; to go back to the old path, `~/Projects/local_llm/bin/qwen-server-run.sh`
still exists until step 8 and reads `.config`, which is still in place.

**Flash-Next stays hand-launched** until the owner installs `/etc/sysctl.d/90-vllm.conf`
(`vm.swappiness=10`, `kernel.yama.ptrace_scope=0`). Its registry entry carries `needs_tty = true`
and v2 refuses to start it unattended rather than failing halfway.

## Step 8 — Archive `local_llm`

Only after a full day of v2 serving without a surprise.

```
grep -rn 'local_llm/\.config' ~/Projects --include='*.py' --include='*.sh' --include='*.toml'   # must be empty
mv ~/Projects/local_llm ~/Projects/archive/local_llm-2026-09-12
```
Keep `.venv-llm-029` where it is — v2's `stock` build points at it (`builds/stock/MANIFEST.toml`).
Leave a `README.md` in its place pointing at this repo.
**Undo:** move it back; nothing else references the new path.

## Step 9 — `v2` → `main`, push (owner-gated)

Merge, run the whole suite plus the acceptance gate one final time, then push. `main` moves only when
the owner says so.

## What the cutover must not lose

- The GLM and Flash-Next fork patches: held as files in `builds/patches/`, and `builds/*/check.sh`
  fails if a fork's working tree drifts from them.
- Every model name any client has ever used: they are `aliases` in `models.toml`, passed to
  `--served-model-name`, so the 404s of 09-11 and 09-12 cannot recur.
- The measured knowledge in `state/measurements.json` (v1) — v2 reads it for its trust badges.
